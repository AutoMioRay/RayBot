## 三、性能优化（需求 2）

按 `提速.md` 12 项逐项评估（完整论证见《性能优化报告》），核心实施：

1. **orjson 编解码层**（`_json.py`，带 stdlib 回退）：WS 收发、HTTP 请求体（预序列化 + 重试复用）、响应体、去重键指纹——实测解码 **2.4~2.5x**、编码 **9.8x**；
2. **EventBus 订阅解析缓存化**：每事件"两次列表拷贝 + 冗余排序"→ 按事件名缓存 tuple，**3.2x**；
3. **背压策略补全**：`overflow="drop"`（丢弃+计数+分级告警）与 `"block"`（默认）双语义；
4. **轻量观测**：`GatewayClient.stats` / `EventBus.stats` 计数器（替代重型 OTel）；
5. **上传哈希出事件循环**（to_thread）、**HTTP/2 实测否决**（官方 API ALPN 仅 http/1.1）、**uvloop 可选组**（Windows 不可用，非 Windows 可装）、**token 预刷新+单飞确认在位并增强**。

否决项均有一手证据（h2 为真机 ALPN 协商实测）或结构性理由（宽松解析是平台兼容的刻意设计），详见专项报告第三节。

## 四、安全测试与修复（需求 3）

### 4.1 测试方案

按《安全测试.md》五层执行，范围锁定 WebSocket 侧（Webhook 已封藏自然出圈）：

- **L1 静态**：bandit（0 命中 / 6133 SLOC，问题密度 0.0/KLOC ≤ 目标 0.5）+ ruff 新增 `S` 规则集（0 error）+ 自定义 grep（无 `verify=False`/`eval`/`exec`/`pickle`/硬编码凭证/裸 except）。
- **L2 单元**：凭证五项（内存驻留、日志零泄露、异常栈零泄露、secret 仅在请求体、单飞）、解析器 Fuzz（hypothesis 递归策略 ~8,000 样本 × 4 属性测试 + 定向边界：深度炸弹 10k 层、2MB 字段、重复键、Unicode 边界、非法 UTF-8、未知 opcode）。
- **L3 协议**：13 个用例驱动真实 WS 客户端 × 本地可编程服务器——关闭码分支（4004/4006/4009/4914/4915/未知）、Identify↔Resume 切换、op9 两种分支、心跳 ACK 超时、心跳间隔钳制、Identify token 不进 header、退避公式、重连上限、网关 URL 白名单矩阵。
- **L4 端到端**：背压（block 阻塞证明 / drop 零阻塞 + 守恒断言）、500 并发发布零丢失、单 worker 严格有序、重连上限耗尽。
- **L5 渗透模拟**：本地自签证书 TLS MITM（token 零泄露）、畸形帧/二进制垃圾/超大帧轰炸、恶意网关 URL fail-closed、日志卫生（对抗流量下 DEBUG 级仍无 token）。

### 4.2 发现与修复（14 项全部闭环）

High 1 / Medium 5 / Low 5 / Info 2，摘要（完整复现与修复见《漏洞修复报告》）：

- **V-01 High**：深度嵌套 JSON 的 `RecursionError` 逃逸 `_decode`，恶意服务器可致 shard 连接任务崩溃——捕获 + orjson 深度上限双重修复；
- **V-02** 心跳间隔钳制（防洪泛/饿死）；**V-03** 4004 致命化（防无限重连）；**V-04** 网关 URL scheme+域名白名单（防 token 外发/SSRF）；**V-05** force_refresh 单飞（防令牌接口风暴）；**V-06** `GatewayError.__str__` 自崩溃修复；
- **V-07~V-11**：presigned URL 强制 https、`mention()` 转义、上传哈希出循环、上传并发封顶 16、凭据格式校验（防日志/JSON 注入）；
- **V-12~V-14**：哈希 `usedforsecurity=False` 语义化（bandit 清零）、Webhook 风险整体封藏、net.py 死代码清理。
