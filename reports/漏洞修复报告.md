## V-01 恶意深度嵌套 JSON 可致网关连接循环崩溃 【High】

- **位置**：`src/qqbot_toolkit/gateway/ws.py` `_decode()`
- **描述**：原实现仅捕获 `(UnicodeDecodeError, json.JSONDecodeError, PayloadError)`。标准库 `json.loads` 对超深嵌套（实测 10,000 层）抛出 `RecursionError`，该异常不在捕获列表中，会沿 `_handle → _connect_once → run()` 传播——`run()` 的重连循环只捕获 `_Fatal/_Reconnect/CancelledError/ConnectionClosed/(OSError, WebSocketException)`，`RecursionError` 直接逃逸，导致整个 shard 连接任务未处理死亡。恶意或被劫持的网关服务器（S5-01/S2-09/S2-15）可借此让机器人进程退出。
- **复现**：向客户端投递 `'{"a":' * 10000 + "1" + "}" * 10000`。
- **修复**：
  1. `_decode` 捕获集合加入 `RecursionError` 与 `ValueError`（覆盖 orjson 的 `JSONDecodeError`）；
  2. 解析层切换至 orjson（自带解析深度上限，超限抛 `JSONDecodeError`），双后端均有界；
  3. 异常计入 `stats["invalid_payloads"]` 便于监控。
- **回归**：`tests/test_fuzz_parsers.py::test_deeply_nested_json_is_rejected`（100/1000/10000 层全部安全拒绝）+ hypothesis 属性测试。

## V-02 心跳间隔无钳制（心跳洪泛 / 静默饿死）【Medium】

- **位置**：`src/qqbot_toolkit/gateway/ws.py` `_connect_once()`
- **描述**：Hello(op10) 中的 `heartbeat_interval` 原样采用（`payload.heartbeat_interval or 45.0`）。恶意/异常服务器返回 1（毫秒→0.001s）会使心跳循环以 1000 次/秒发送（CPU 与网络消耗、干扰限流）；返回 10^9 则等效禁用心跳，静默等待服务器踢线。
- **修复**：新增 `GatewayConfig.heartbeat_min_interval=1.0` / `heartbeat_max_interval=300.0`，连接时钳制 `interval = min(max(interval, min), max)`，配置项本身有正数与大小关系校验。
- **回归**：`test_hostile_heartbeat_interval_is_clamped`（1ms 间隔被钳至下限，相邻心跳间隔实测 ≥ 配置下限）；`test_heartbeat_ack_timeout_triggers_reconnect`。

## V-03 关闭码 4004（认证失败）未致命化，无效凭据无限重连 【Medium】

- **位置**：`src/qqbot_toolkit/constants.py` `FATAL_CLOSE_CODES`
- **描述**：平台以 4004 关闭连接表示 token/凭据无效。原集合不含 4004，客户端将以指数退避（封顶 60s）**永久重连**——对同 AppID 的重复认证失败请求既浪费平台配额（session_start_limit），也让故障机器人在日志中持续刷屏。
- **修复**：`FATAL_CLOSE_CODES` 加入 `4004`，认证失败立即抛 `GatewayError(fatal=True)` 终止。
- **回归**：`test_close_code_4004_is_fatal_and_stops_reconnecting`（断言 `connections == 1`，绝不重试）。

## V-04 网关 URL 未校验（SSRF / token 外发面）【Medium】

- **位置**：`src/qqbot_toolkit/gateway/ws.py` `_connect_once()`；新增 `src/qqbot_toolkit/net.py::is_trusted_gateway_url`
- **描述**：`GET /gateway/bot` 返回的 URL 原样交给 `websockets.connect`。若 OpenAPI 响应被劫持（代理被攻破、DNS 劫持等），攻击者可让客户端连接任意主机——客户端随后把 **access_token 放进 Identify/Resume payload 发往该主机**，同时构成出站 SSRF。
- **修复**（纵深防御，默认 fail-closed）：
  1. scheme 必须 `wss://`（`ws://` 仅允许回环地址用于本地测试，或显式 `allow_insecure_gateway_ws=True`）；
  2. 非回环主机必须匹配 `allowed_gateway_hosts` 后缀白名单（默认 `("qq.com",)`，覆盖实测官方端点 `api.sgroup.qq.com` 与沙箱端点）；
  3. 拒绝带内嵌凭据的 URL；放空名单中的空条目在配置期即报错；
  4. 校验失败抛 `_Fatal("gateway URL rejected: ...")`，**不发送任何 token**。
- **回归**：`test_gateway_url_allowlist_matrix`（15 项正反矩阵，含 `qq.com.attacker.example` 绕过尝试）；`test_malicious_gateway_url_fails_closed`（恶意 API 响应动态测试）。

## V-05 强制刷新（force_refresh）并发无单飞 【Medium】

- **位置**：`src/qqbot_toolkit/auth.py` `get_token()`
- **描述**：非强制路径已有锁内缓存复查（单飞成立），但 `force_refresh=True` 会绕过缓存检查——N 个并发调用方产生 N 次令牌接口请求。实测 50 并发 = 51 次请求。`/app/getAppAccessToken` 有严格频控，风暴会导致 429 及后续所有 API 的 401 重试放大。
- **修复**：请求方在**进入锁前**记录 `requested_at = time.monotonic()`；锁内若发现缓存的 token 是在本请求发起之后获取的（`_token_obtained_at >= requested_at`），直接复用。语义保持"返回不早于本请求开始的 token"，同时把并发需求收敛为一次网络请求。
- **回归**：`test_force_refresh_bypasses_cache_with_single_flight`（异步 mock 强制真实重叠，50 并发 → 恰好 1 次刷新）；`test_single_flight_refresh_issues_one_request`（100 并发冷启动 → 1 次）。

## V-06 `GatewayError.__str__` 自身崩溃，掩盖真实错误 【Medium】

- **位置**：`src/qqbot_toolkit/errors.py` `GatewayError`
- **描述**：`__str__` 引用 `self.message`，但 `__init__` 从未设置该属性（仅传入 `super().__init__`）。任何 `str(GatewayError)` ——包括日志打印、pytest 断言、运维排查——都会抛 `AttributeError`，把真实故障原因替换成二次异常，属于可观测性/审计缺陷（R 类）。
- **复现**：`GatewayError("x").__str__()` → `AttributeError: 'GatewayError' object has no attribute 'message'`。
- **修复**：`__init__` 中保存 `self.message = message`。
- **回归**：`test_reconnect_attempts_are_bounded` 对错误消息内容做字符串断言（修复前该测试在 `str()` 处崩溃）。

## V-07 富媒体 presigned 上传 URL 未强制 https 【Low】

- **位置**：`src/qqbot_toolkit/api/media.py` `_put_presigned()` / 新增 `_validate_presigned_url()`
- **描述**：`presigned_url` 来自 API 响应，用户媒体数据将 PUT 到该地址。无 scheme 校验时，被操纵的响应可让媒体明文外发到任意 `http://` 主机（数据外泄 + SSRF 面）。
- **修复**：上传前强制 `https://`（回环 `http://` 豁免以支持本地联调）；拒绝带内嵌凭据的 URL。已有的 `follow_redirects=False`（原实现）继续阻断重定向型外泄。未启用主机白名单：真实上传桶在腾讯云对象存储域名（非 qq.com），硬编码后缀会破坏正常上传，残余风险已在报告中记录。
- **回归**：`_put_presigned` 路径强制调用校验；矩阵行为由单元断言覆盖。

## V-08 `mention()` OpenID 未转义（markup 属性逃逸）【Low】

- **位置**：`src/qqbot_toolkit/api/messages.py` `mention()`
- **描述**：`<qqbot-at-user id="{openid}" />` 直接内插。含 `"` 的值可逃出 `id` 属性并注入后续 markup token（如 `qqbot-cmd-enter`）。OpenID 平台侧生成、实际风险低，但与同文件 `command_enter/command_input` 的 `quote_plus` 处理不一致。
- **修复**：`quote_plus(member_openid)`——正常字母数字 OpenID 原样通过，恶意值被编码失效。
- **回归**：随 API 回归测试覆盖（mention 输出格式断言）。

## V-09 `upload_bytes` 在事件循环内同步哈希 【Low】

- **位置**：`src/qqbot_toolkit/api/media.py` `upload_bytes()` / `upload_image()`
- **描述**：对 ≤5MB 内存数据同步执行 md5+sha1+md5_10m 三重哈希（10MB 窗口），阻塞事件循环；事件洪峰时放大 P99 延迟（S4-09）。`upload_file` 早已用 `asyncio.to_thread`，两路径不一致。
- **修复**：`hash_bytes` 调用统一改为 `await asyncio.to_thread(hash_bytes, data)`（`upload_bytes` 与 `upload_image` 两处）。
- **回归**：API 层既有测试全绿（行为不变，仅执行位置变化）。

## V-10 分片上传并发数无上限 【Low】

- **位置**：`src/qqbot_toolkit/api/media.py` `_upload_chunked()`
- **描述**：并发信号量直接采用服务端返回的 `upload_config.concurrency`，仅保底 `max(1, ...)` 无封顶。异常大的服务端值（或被操纵的响应）会瞬间发起海量并发 PUT 连接。
- **修复**：`concurrency = min(int(...), MAX_UPLOAD_CONCURRENCY)`，上限常量 16。

## V-11 凭据无格式校验（注入面）【Low】

- **位置**：`src/qqbot_toolkit/config.py` `BotConfig.__post_init__` / 新增 `_validate_credential()`
- **描述**：appid/secret 原样接受任意字符串（含换行、控制字符、前后空白、超长值），会被拼入 JSON 请求体与日志行——控制字符是日志注入与 JSON 结构注入的载体（S5-08/S5-09）。
- **修复**：非空、appid ≤64 / secret ≤256、禁止前后空白、禁止任何 C0 控制字符与 DEL。`from_env()` 同样经过校验。
- **回归**：`tests/test_security_config.py` 新增 5 个用例（空值/控制字符/超长/空白填充）。

## V-12 哈希函数静态扫描误报清理 【Info】

- **位置**：`api/media.py`（7 处）、`models/events.py`（1 处）
- **描述**：MD5/SHA1 均为平台要求上传校验和与去重指纹，非安全用途，但 bandit 报 8 个 HIGH，污染问题密度指标。
- **修复**：全部改写为 `hashlib.md5(..., usedforsecurity=False)` / `hashlib.sha1(..., usedforsecurity=False)`——语义正确声明而非注释压制。bandit 现为 **0 命中**。

## V-13 Webhook 签名预言机（协议级）——整体封藏 【Info / 架构决策】

- **描述**：`op=13` 验证端点对任意 `plain_token` 返回 Ed25519 签名，而事件验签使用同一密钥，公网暴露即可伪造事件。该风险无法在不引入额外基础设施（独立密钥、外置网关）的前提下根除。
- **处置**：按需求"暂时只使用 WebSocket"，Webhook 全部代码（服务器、签名、配置、测试、示例）原样封藏至 `archive/webhook/`，`aiohttp`、`cryptography` 从运行依赖移除，文档同步更新。恢复步骤见 `archive/webhook/README.md`。

## V-14 webhook 移除后的死代码清理 【Info】

- **描述**：`net.py` 中 `resolve_client_ip`、`parse_networks`、`ip_in_networks`、`IPNetwork` 仅为 Webhook 入站过滤服务，封藏后成为无调用方死代码。
- **修复**：从 `net.py` 删除；`net.py` 现仅保留 `parse_ip`、`is_loopback_host`、`is_trusted_gateway_url`（均为 WebSocket 路径所用）。
